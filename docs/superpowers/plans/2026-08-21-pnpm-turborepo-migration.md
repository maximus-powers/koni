# pnpm and Turborepo Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert Koni's development repository to pnpm and Turborepo with local task caching and
bounded parallel core tests while preserving npm as the Pi publication/runtime compatibility
boundary.

**Architecture:** pnpm owns workspace discovery and dependency installation; Turbo owns the
workspace task graph and local cache. Core Vitest tests are divided by a centralized classification
into a four-worker isolated lane and a single-worker exclusive lane. npm lock data needed to verify
Pi's real install closure becomes an explicit fixture rather than the repository lockfile.

**Tech Stack:** Node.js 22.19+, pnpm 11.13.1, Turborepo 2.10.5, Vitest 4.1.10, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-08-21-pnpm-turborepo-migration-design.md`

## Global Constraints

- Repository development uses pnpm 11.13.1; no root npm workspace orchestration remains.
- Turborepo 2.10.5 caches deterministic tasks only in the local `.turbo` cache.
- No hosted remote cache, remote-cache URL, team, token, or CI cache transport is added.
- npm remains the package publication, stock-Pi installation, audit, SBOM, and registry boundary.
- Pi host compatibility stays pinned to Pi 0.80.10 and TypeBox 1.1.38 using npm lockfile v3 data.
- Parallel core tests use isolated fork workers and at most four workers.
- Tests with genuinely shared process/OS state remain in a one-file-at-a-time exclusive lane.
- Every core `*.test.ts` file belongs to exactly one test lane.
- Historical plans/specifications and npm package coordinates are not rewritten.
- Do not repeatedly run the full suite; use focused checks until the single final integration run.

```js
test("the repository is a pinned pnpm Turborepo", async () => {
  const manifest = await readJson("package.json");
  assert.equal(manifest.packageManager, "pnpm@11.13.1");
  assert.equal(manifest.devDependencies?.turbo, "2.10.5");
  assert.equal(manifest.workspaces, undefined);
  assert.match(await read("pnpm-workspace.yaml"), /packages:\s*\n\s*- packages\/\*/u);
```

**Interfaces:**

- Consumes: the shared Core Vitest defaults and the complete set of `test/*.test.ts` files.
- Produces: `exclusiveTestFiles: readonly string[]`, two disjoint Vitest configurations, and package
  scripts `test:parallel`, `test:exclusive`, and `test:file`.

- [ ] **Step 1: Write the failing lane-classification test**

Create `test/test-lanes.test.ts` that imports `exclusiveTestFiles`, enumerates direct
`test/*.test.ts` files, normalizes all paths to `test/<name>.test.ts`, and asserts:

```ts
expect(new Set(exclusiveTestFiles).size).toBe(exclusiveTestFiles.length);
expect(exclusiveTestFiles.every((file) => allTests.includes(file))).toBe(true);
expect(allTests.filter((file) => !exclusiveTestFiles.includes(file))).not.toHaveLength(0);
expect([...exclusiveTestFiles, ...parallelFiles].sort()).toEqual(allTests.sort());
```

It must also assert that every exclusive entry has a short documented reason in an exported
`exclusiveTestReasons` record and that no unknown reason key exists.

- [ ] **Step 2: Run the test and verify RED**

Run:

```sh

```

Expected: FAIL because `test-lanes.ts` does not exist.

- [ ] **Step 3: Implement centralized lane classification**

Create `test/test-lanes.ts` with repository-relative `test/<file>.test.ts` entries. Classify only
tests proven to depend on shared or timing-sensitive process state as exclusive; real child/Git use
inside a unique temporary directory is not by itself shared state. Start with the process-supervisor
and authority lifecycle files identified by the source audit, and document the resource reason for
each entry. Keep the list sorted.

- [ ] **Step 4: Refactor shared Vitest defaults**

Export a plain `coreTestDefaults` object from `vitest.config.ts` containing setup files, fork pool,
20-second test/hook deadlines, and other common settings. Remove global `fileParallelism: false`.
Keep the default config suitable for targeted `test:file` invocations.

Create `vitest.parallel.config.ts` by merging the shared config with:

```ts
{
  fileParallelism: true,
  maxWorkers: 4,
  exclude: [...configDefaults.exclude, ...exclusiveTestFiles],
}
```

Create `vitest.exclusive.config.ts` with:

```ts
{
  include: exclusiveTestFiles,
  fileParallelism: false,
  maxWorkers: 1,
}
```

- [ ] **Step 5: Add Core test scripts**

Set the Core scripts to:

```json
{
  "test": "pnpm run test:parallel && pnpm run test:exclusive",
  "test:parallel": "vitest run --config vitest.parallel.config.ts",
  "test:exclusive": "vitest run --config vitest.exclusive.config.ts",
  "test:file": "vitest run"
}
```

Retain the existing `check` behavior using pnpm composition.

- [ ] **Step 6: Verify GREEN and stress the risky boundary without a full run**

Run:

